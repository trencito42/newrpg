# Panel deployment notes

1. Rotate the MariaDB credential previously committed in `panel/src/lib/db.ts`; Git history still contains it. Put the replacement in private deployment configuration, not source control.
2. Configure `panel/.env.local` from `panel/.env.example`. All five `DB_*` values are required. Configure the public brand, connect address and Discord URL as desired. `SESSION_SECRET` is documented for deployment compatibility; session token generation itself uses cryptographic randomness.
3. Install dependencies with `cd panel && npm ci`; run `npm test`, `npx tsc --noEmit`, and `npm run build`.
4. Apply the repository migrations to the selected MariaDB database. `sql/65-panel-schema.sql` creates panel tables; `sql/66-panel-hardening.sql` removes the unused PIN table, adds the poll integrity key and creates `panel_runtime_snapshot`. `scripts/apply-migrations.sh` strips historical hardcoded `USE` statements during import while preserving checksums. Back up data before new migrations. If v65 was imported manually, verify all its tables before baselining its checksum in `schema_migrations`.
5. Start the `sunset_panel_bridge` FiveM resource after v66, then verify `panel_runtime_snapshot.updated_at` advances. If it does not, the panel correctly reports the server offline. There is no `127.0.0.1:30121` HTTP service.
6. Bind Next.js to loopback behind an HTTPS reverse proxy. Set `PANEL_PUBLIC_ORIGIN` to the public HTTPS origin. Set `PANEL_TRUST_PROXY=1` only if that proxy overwrites `X-Real-IP` and preserves the public `Host` and `Origin`. Add proxy-side login rate limiting. Do not forward arbitrary client-supplied proxy headers. Restart the panel process after replacing its build.

Do not expose the staff dashboard as proof of web moderation: it remains read-only until a tested FiveM action queue/consumer is implemented. The seeded v65 mayor poll is removed by v66 only if it has no votes. A poll with real votes is intentionally retained for manual review rather than deleting voter data.
